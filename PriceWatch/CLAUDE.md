# PriceWatch — WMSPriceWatch.exe

Загружается, когда работа идёт в `PriceWatch/`. Общие правила (кодировка, сборка) — в корневом `CLAUDE.md`. Рядом лежит парный `AGENTS.md` — держи оба одинаковыми.

`WMSPriceWatch.exe` (`PriceWatch/WMSPriceWatch.dpr`) — **мониторинг цен конкурентов** (xstore.md, neocomputer.md, geek.md; список — таблица `TWEB_COMPETITOR_SITES`). Работает **круглосуточно** как оконное приложение: поток `TPWMonitorThread` по кругу обходит активные категории (`TWEB_COMPETITOR_CATEGORIES` ↔ `TWEB_CATALOG`, URL каждой категории на каждом сайте — `TWEB_COMPETITOR_CAT_URLS`), извлекает товары и цены **regex-ами из базы** (колонки `*_REGEX` сайта — новый конкурент = новая строка, без перекомпиляции), пишет их в `TWEB_COMPETITOR_ITEMS` (история — триггерами в `TWEB_COMPETITOR_PRICE_HIST`) и сопоставляет с нашими товарами, активными на сайте (`SP_COMPETITOR_OUR_GOODS` = выборка `W_V2_GET_GOODS_LIST_BY_CATALOG2`, цена `PRICE1_LEI` минус промо-скидка). Раз в `REPORT_INTERVAL_MIN` минут (по умолчанию 180) главная форма строит Excel (`TdxSpreadSheet`, листы Rezumat / Detalii / Modificari / Neasociate / Fara concurenta) и шлёт его в Telegram через `TelegramSendDocument` (`sources/Utils/TelegramApiUnit.pas`) в канал `TELEGRAM_CHANNELS` из настройки `TELEGRAM_CHANNEL` (по умолчанию `PRICELISTS` = «Online :: Fantastic»).

- **Схема:** `DB Model/competitor_prices.sql` (повторно запускаемый; откат — `competitor_prices_rollback.sql`), там же стартовые строки для трёх сайтов и шести категорий (CPU 132, платы 134, память 135, SSD 928, HDD 139, видео 136) и настройки `TS_API_CONFIG` / `API_CODE = COMPETITORS` (`REPORT_INTERVAL_MIN`, `CYCLE_PAUSE_MIN`, `TELEGRAM_CHANNEL`, `PROXY_URL`, `MIN_SCORE`, `REPORT_DIR`).
- **Защита от блокировок** (`PWHttpUnit`): случайная пауза `DELAY_MIN_MS..DELAY_MAX_MS` между запросами к одному сайту (xstore 8–15 с, остальные 4–9 с), ротация User-Agent, браузерные заголовки, cookie, прокси (сайта или глобальный `http://user:pass@host:port`); при 403/429/503, странице капчи (`BLOCK_REGEX`) или сетевой ошибке сайт уходит в паузу `BLOCKED_UNTIL` с ростом 10→20→40 мин … до 6 ч (`PWMonitorThread.BlockSite`). Между полными циклами — `CYCLE_PAUSE_MIN`. **xstore.md периодически перестаёт отвечать WinHTTP** (THTTPClient: «Error sending data (12002)», при этом curl отвечает за 0,5 с) — при такой ошибке запрос повторяется через `curl.exe` из System32 (`TPWFetcher.CurlGet`), и сайт до перезапуска программы ходит через curl.
- **Сопоставление** (`PWMatchUnit`): ключевые токены с цифрами (12400F, 9800X3D, B760M-HDV, SNV3S1000G), без единиц измерения (16GB, 3.6GHZ, 65W; «3.6 GHz» склеивается в один токен); суффиксы X/K/G у 4-значных моделей (7600X, 14600K, 3200G) — часть модели, у коротких (2X, 4K, 16G) — единицы; вес IDF; принимается лучший кандидат при сумме ≥ `MIN_SCORE` (2.5) и хотя бы одном редком общем токене. Отклоняется при конфликте семейства (i5/i7, Ryzen 5/7, DDR4/5), упаковки (BOX/TRAY), ёмкости (500GB/1TB, дробные 1.0TB), **бренда платы/накопителя** (Gigabyte ≠ Biostar; у нас бренд берётся из `VENDOR`, если его нет в названии) и при несовпадении набора вариантов/серий (TI, SUPER, XT, PRO, OC, AORUS, WINDFORCE, TUF, VENTUS …). Ручная связь (`MATCH_TYPE` 2) и ручной отказ (3) автоматикой не трогаются — кнопки на вкладке «Produse la concurenti».
- **Ловушка домена `DM_VARCHAR512`:** в базе он объявлен как 512 **байт** UTF8 = 128 символов (ошибка «string right truncation, expected length 128»), поэтому длинные тексты в таблицах `TWEB_COMPETITOR_*` на `DM_VARCHAR1024`; секция 9 DDL переводит уже созданные колонки.
- **UI в стиле SWN** на общих библиотеках (DevExpress cxGrid, IBDAC, `TDialogTitle`, Segoe UI), базовая форма `PWBaseFormUnit.TPWCustomForm` повторяет `Prepare / IsFormDataPosted / WhenCancelForm` из `SWNBaseUnit` (сам `SWNBaseUnit` не подключён: он тянет `DataModuleDB` и все ~840 юнитов WMS). Вход — `PWLoginDialog` через `CAN_USER_LOGIN2` + `CreateHashPassword` (`SWNSecurityUtils`); `/auto` — без входа, технический аккаунт из `SWNConst`, монитор стартует сам (для автозапуска с Windows); `/server:ADDR`.
- **Диалог «Site-uri»** → вкладка «Testeaza parsarea»: скачивает одну страницу категории и показывает, что вытащили regex-ы — так настраивается новый сайт. geek.md отдаёт HTML после PageSpeed **без кавычек** у атрибутов (`class=main_item_lg_title`, `data-price-base=3660.0000`) — regex-ы должны допускать обе формы; xstore.md игнорирует `?limit=` (24/стр., 404 после последней), neocomputer.md и geek.md принимают `?limit=100`.
- **Сборка:** `msbuild PriceWatch/WMSPriceWatch.dproj /p:Config=Release /p:Platform=Win32` → `exe/WMSPriceWatch.exe`, DCU в `dcu/WMSPriceWatch/`. В `wms project.groupproj` не входит. Журналы: `logs/pricewatch_YYYYMMDD.log` рядом с exe, отчёты — `reports/` (или `REPORT_DIR`). Ключ `/report:N` — первый отчёт через N минут после старта (для проверки).
- **Ловушки IBDAC:** один и тот же параметр дважды в SQL (`:SITEID = 0 OR i.SITEID = :SITEID`) даёт «Wrong number of parameters (expected 5, got 3)» — нужны разные имена; внутри `with Query do` имя `Name` попадает в `TComponent.Name`.
- **Полный цикл (20.10.2026):** 18 URL, ~2 500 товаров конкурентов, около 9 минут; geek/neocomputer по 2–4 страницы (`?limit=100`), xstore до 21 страницы (SSD).
